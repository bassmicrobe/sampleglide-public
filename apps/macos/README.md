# SampleGlide macOS client

Native SwiftUI / AppKit application, macOS 14+, Swift 5.10+ (built/tested on Swift 6.3.3, Apple Silicon, macOS 26). Intel and macOS 14 runtime behavior are not yet device-tested. The client owns a local SQLite index for mounted folders; this public repository does not include the optional Rust NAS service, SQL migrations, external design package, or copied API specification files. The retained shared-index UI requires a separately supplied compatible API. Local browsing, search and preview require neither Rust FFI nor server setup.

```sh
swift run --package-path apps/macos SampleGlide
apps/macos/scripts/build-app.sh
open 'apps/macos/dist/SampleGlide.app'
swift test --package-path apps/macos
```

`build-app.sh debug` creates a faster local development bundle. The app is ad-hoc signed, not notarized or prepared for public distribution. The build runs in the selected checkout and does not install in `/Applications`.

SampleGlide is the public app and SwiftPM executable product name. The internal `SampleBrowser` module, `SampleBrowserAssets` resource target, `jp.samplebrowser` identifiers (including the bundle identifier and Keychain services), existing settings/data locations, and `~/Music/Sample Browser Exports` remain unchanged from Sample Browser to preserve favorites, settings, credentials, and DAW file references. No data migration is required.

The app icon source is [`Assets/AppIcon.png`](Assets/AppIcon.png), a square PNG of at least 1024 × 1024 pixels. Every bundle build runs `scripts/build-icon.sh` using macOS `sips` and `iconutil` to generate all standard 16–512 point icon sizes at 1× and 2×. The resulting `Contents/Resources/AppIcon.icns` is referenced by `CFBundleIconFile` and retained as the original-artwork fallback.

The same artwork appears beside the name at the top of the sidebar. `SampleBrowserAssets` bundles the PNG for SwiftPM development runs; the app build copies that resource bundle into `Contents/Resources` before signing, so the sidebar artwork also works independently of the checkout.

With full Xcode 26 or later selected, `scripts/build-icon-catalog.sh` also stages an Icon Composer document from [`Assets/AppIcon.icon.json`](Assets/AppIcon.icon.json) and the same PNG, then compiles it with `actool`. The resulting `Assets.car` and `CFBundleIconName = AppIcon` enable the native icon on macOS 26, avoiding the white backing that macOS can add to large legacy-icon representations. This uses the single-image document structure from [Apple's alternate app icons sample](https://developer.apple.com/documentation/xcode/configuring-your-app-to-use-alternate-app-icons). Both resources are added before signing, and temporary documents and iconsets are removed automatically. The source artwork is not duplicated or modified.

Command Line Tools and older Xcode builds use ICNS only; the build removes any stale `Assets.car` and omits `CFBundleIconName` in that case. Compilation failures with an available Xcode 26+ stop the build. To rebuild just the resources, run `apps/macos/scripts/build-icon.sh` (output: `apps/macos/.build/AppIcon.icns`) and `apps/macos/scripts/build-icon-catalog.sh` (output: `apps/macos/.build/AppIconCatalog/Assets.car` when supported). Replacing the source PNG and rebuilding the bundle updates both formats.

## Local library search

The sidebar's “全体検索” searches all registered places, including their nested directories and WAV/AIFF/FLAC files. The folder search field defaults to “すべての場所”; choosing “このフォルダ” instead filters only the rightmost visible column. “メモ・タグ検索” remains a separate view of annotated items only, and “共有索引” uses the optional server API.

- [`LocalLibrarySearchModel`](Sources/SampleBrowser/LocalLibrarySearchModel.swift) begins background enumeration for new sources and resumes the durable unfinished queue after interruption. A completed source remains complete across launches; automatic periodic full scans are not started. “全体を更新” explicitly starts a fresh generation from the root. Pause/resume is available in the search pane and persists in UserDefaults.
- [`LocalSearchIndexStore`](Sources/SampleBrowser/LocalSearchIndexStore.swift) stores metadata and checkpoints in `~/Library/Application Support/jp.samplebrowser/library-index.sqlite3`. SQLite access is actor-isolated; directory I/O runs on a separate utility queue. Searches can use committed batches while the first crawl continues. Hidden items, symbolic links and Finder aliases are skipped. Indexing does not copy audio, decode waveforms, or analyze BPM/key.
- Search combines literal partial matches across name, path, notes and tags; whitespace-separated terms use AND and `#tag` restricts a term to tags. Queries are debounced/cancelled, results use stable cached path IDs, and “さらに読み込む” appends one bounded 200-row page. Index/metadata refreshes reconcile the visible prefix. Ordered candidate pages are materialized before source/annotation hydration; frequent status reads cache membership counts for up to five seconds, with fresh terminal counts. Unchanged sources no longer trigger a whole-index orphan sweep during startup or annotation edits.
- Directory progress uses an indeterminate linear bar only while traversal is running, with persisted processed/pending directory counts. Pausing or ending traversal removes the animation. An exhausted queue with errors shows that traversal ended with unreadable places; it never displays a new 0% scan or claims full successful completion.
- File click/up/down selection stays in the results list and uses the automatic-preview setting. Background index or metadata updates do not restart an unchanged selection. Directories are selected with one click and opened with double-click, Return or Right. Context menus expose notes/tags, file/directory favorites and collection membership, alias renaming, folder navigation and Finder reveal.
- Offline sources retain cached results and show a retryable error. Cached metadata does not make the original audio available offline; preview and navigation still need the mounted source. The first crawl may take time on a large NAS, and uncrawled material will not yet appear. A successful real-NAS scan checkpoint was recorded on 2026-09-19; the 2026-09-21 update preserved approximately 3.99 million indexed items and resumed the ongoing scan. A 6 TB performance benchmark remains unverified.
- Failed directory reads get two bounded retries, eligible after 2 and 10 seconds. Other ready directories continue during backoff. Retry attempts and deadlines survive pause/restart; only a successful or exhausted directory increments the processed count. Errors include the directory path, and exhausted failures retain the previous index without pruning inaccessible subtrees.

## Working operations

- Mounted-file and directory notes/tags can be edited from the row context menu or the “メモ・タグ” button, without shared API setup. The same metadata appears in folder columns, global search and Favorites. “メモ・タグ検索” searches only annotated items across folders with tag chips, name/notes/tag text, and `#tag` tokens; whitespace-separated terms use AND. The current-folder and Favorite filters also include notes/tags. Metadata is saved atomically in `~/Library/Application Support/jp.samplebrowser/annotations.json` and reflected in the local search index; source-relative identities follow resolved mount paths, and originals are untouched. This Mac's annotations and the optional shared-index annotations remain separate.
- Finder-style folder columns for Mac and already-mounted NAS volumes. Add source folders, navigate one level at a time, and select audio to automatically load its waveform and play the original audio. Columns remain usable while the background index is incomplete. Up/down move selection within the focused column. Right enters the selected directory and selects its first item after loading; Left closes the child columns and returns to the parent directory. Empty/loading columns retain keyboard navigation, and the registered source is the parent-navigation boundary. Text-entry arrows keep their native cursor behavior. Automatic playback is on by default, can be switched off in the audio panel or Playback Settings (Cmd+,), and persists on this Mac. API credentials are not required.
- Multiple named favorite folders can be created and renamed from the sidebar or Favorites header; these are app-local collections. The named-folder context submenu lets a file/directory belong to multiple collections. Removing a collection or a membership retains the global favorite. Version1 preferences migrate in memory into a default folder; the next explicit save writes version2 and retains source bookmarks, aliases and relative paths.
- Right-click file/directory favorites with local display aliases. Clicking a file favorite plays it in place without leaving the Favorites list (an explicit play action, even when automatic selection playback is off); folder favorites still navigate. The file context menu offers “フォルダで表示” for explicit navigation. Favorite previews resolve bookmarks without listing parent folders, and cancel stale navigation/preview results; source names/content are never changed. Preferences are stored atomically in `~/Library/Application Support/jp.samplebrowser/folders.json`; root bookmarks and relative favorite paths help resolve mounted locations. Favorite/source persistence is local to this Mac. Shared-index file favorites retain their server API behavior and offer local display aliases too.
- Favorites and note/tag results support Up/Down selection with the automatic-preview setting, while click/Return explicitly plays or opens. Saved normalized paths and annotation search fields/order/results are cached; drawing or selecting a row does not re-normalize NAS URLs or re-fold all notes. Folder refresh reloads the rightmost displayed directory and preserves an existing selection/preview regardless of favorite membership.
- Original-file drag readiness is validated from headers/source identity separately from full waveform decoding. Processing/range controls wait for waveform metadata; pending playback shows a cancellable spinner, and playback errors remain visible alongside a loaded waveform. Standard WAV size limits apply only to channel-aware processed exports, not untouched streaming originals.

- Native four-region dark Japanese UI. The optional shared-index API search uses a 250 ms debounce, cancellation, at most 100 result rows retained, and next/previous page cursor history capped at 30; these limits do not describe the local 200-row search pages.
- HTTPS Bearer API connection, token stored in Keychain. Only loopback may use plain HTTP. Redirects are rejected to avoid forwarding credentials. JSON response cap 4 MB.
- Text/BPM range/kind/favorite filters and name/BPM/duration sorting, selected details, optimistic-version favorites/tag diffs/manual BPM/notes. NAS success is displayed only after response; 412 conflicts reload latest state before reapplication. Tag chooser initially fetches first server page only; full tag browsing/creation is pending.
- Open local WAV/AIFF/FLAC via Cmd+O. Actual decoder support depends on Core Audio; decode errors are shown. Streamed 8192-frame reads, <=1024 min/max bins per channel, content fingerprint and source stat consistency, no full index or full waveform audio in RAM.
- Selected NAS audio fetched into a disk cache with a 512 MB per-file cap, then decoded locally. Shared-index playback waits for the selected-file download, then starts independently of peak generation. Mounted NAS files play directly via Core Audio after their header opens. Seekable ranged HTTP streaming and server peak tiles are pending.
- Click the waveform to play from that source position, including when automatic preview is off. Clicking does not change trim bounds or the DAW drag target; drag the start/end handles or edit frame fields to change the half-open range `[start, end)`. Tempo/pitch-adjusted clicks inside the range reuse the prepared edit; clicks outside it prepare a separate full-source audition cache with the same processing, leaving the export selection intact. Manual source/target BPM, ±24 semitone pitch, volume and loop are supported.
- Tempo ratio 0.25–4. Exact rounded output frame length, source sample rate, float32 WAV, optional fade implementation (UI currently exposes zero fades only). Output >standard WAV 4 GB is rejected explicitly. Tempo/pitch processing is limited to mono/stereo; unity trim supports up to 8 channels, with multichannel output-device playback still unverified.
- Original files are never altered. Untouched selections play directly through AVAudioEngine without rendering or waiting for full waveform analysis. Rapid selection changes cancel stale playback. Edited preview processing runs offline in a detached task; changing edits cancels old work and invalidates the old drag URL. Edited playback is not live DSP.
- Preview and export use the same rendering function and parameters. Tempo/pitch uses native stereo AVAudioUnitTimePitch with reversible right-channel polarity normalization for negatively correlated material: direct processing canceled antiphase test material on the tested OS. Channels remain separate throughout DSP; polarity is restored before writing. General stereo-image/artifact quality remains to be evaluated with real samples. Unmodified trim bypasses DSP and copies samples exactly.
- DAW drag uses the original file URL for full-range, unmodified audio: no WAV generation or conversion step. After trimming, tempo, pitch or fade changes, a 220 ms debounce automatically prepares a WAV in `~/Music/Sample Browser Exports`; drag is enabled only for the current completed result. The optional export menu can still explicitly write WAV. Drag uses AppKit `NSDraggingItem(pasteboardWriter: NSURL)` and a copy operation. Generated exports are never automatically deleted. A DAW that references a mounted original needs that volume available unless the DAW copies the media into its project. Intermediate files are hidden in isolated render directories and removed on cancellation/failure/completion.

## Development review

The app accepts `--open /absolute/path.wav` and `--connection-file /absolute/path.json`. The latter file contains `base_url`, `library_id`, and `token_file` (absolute or relative to that JSON). It loads the token into Keychain and refreshes the library without printing credentials. Keychain reads and writes run away from the main UI thread, so an authorization prompt does not freeze the app. Do not commit either the token or local connection file. Secrets are not command-line arguments.

For developer verification, `--session-connection-file /absolute/path.json` uses the same file format but keeps the connection and token only in the current process. It does not update UserDefaults or Keychain. Every NAS operation uses this session connection until the app exits, or the user explicitly saves connection settings in the app. Use only one connection-file option per launch. This is useful when an ad-hoc rebuild needs Keychain authorization but you want to verify against a local test API without changing the saved connection.

`--browse-folder /absolute/path` adds/opens a mounted folder. Normal startup opens the saved folder browser and starts/resumes background indexing of registered places without accessing shared API credentials; a saved pause keeps enumeration stopped. `--shared-index` opens and refreshes the shared-index screen on startup; otherwise it connects when that screen is selected. Explicit connection-file options still initialize their requested API connection.

```sh
open 'apps/macos/dist/SampleGlide.app' --args --connection-file "$PWD/.local/connection.json"
```

Tests generate their own 48 kHz stereo sine fixture and validate half-open selection, exact frame counts across tempo changes, pitch preservation during tempo changes, octave pitch shift, antiphase stereo, bounded peaks, no original modifications, and reusable outputs. A test fixture is not a DAW interoperability or audio-quality certification.
